## 1. 가설과 방향 예측의 근거

목표 자극 500ms 전 테두리 시각 경고 신호가 있으면, 없을 때보다 같은 참가자의 단순 반응시간이 짧아진다.

단측 검정을 쓰는 이유: 중립적 경고 신호 뒤 반응이 빨라진다는 선행 결과(Weinbach & Henik, 2012)에 근거해 방향을 미리 정했다. 반대 방향(신호가 느리게 함)이 나오면 확증 검정의 대상이 아니며, 기술통계와 그림으로 그대로 보고한다.

## 2. 수집 규칙

- 기간: 링크를 처음 공유한 날 D0 00:00부터 D0+6일 23:59(KST)까지. D0에 `analysis/collection_window.json`을 만들어 커밋한다. 분석 코드는 이 파일 없이는 실행되지 않고, `finished_at`이 기간 밖인 판을 제외한다.
- 수집 중에는 분석 스크립트를 실제 데이터에 돌리지 않는다. 확인하는 것은 판·참가자 건수뿐이다(`/stats.html`).
- **기간 연장 없음.** 마감 시점의 분석 가능 인원이 20명보다 적어도 연장하지 않고 그대로 분석한다. 분석 가능 인원이 2명 미만이면 검정 없이 기술통계만 보고한다.
- 앱 버전 2.0.0으로 수집한다. 연구자 파일럿(`?pilot=1`)은 서버의 별도 경로에 저장되고 분석·순위표에 포함하지 않는다.
- 한 사람이 '번개 반사'를 몇 판 할지는 참가자 마음이다. 판 수에 상한을 두지 않는다. 다른 미니게임(컬러 함정, 1→16, 딱 N초, 전후 비교 실험실 '번개 반사 2·3·4')의 기록은 순위표·비교 화면에만 쓰고 이 논문에서 분석하지 않는다. (2026-10-30 수집 전 추가: 게임 목록만 늘었고 분석 규칙은 그대로)

## 3. 제외 규칙

**판 단위 (순서대로 적용, 첫 사유 하나만 기록)**

1. 파일럿 판(`pilot = true`)
2. 수집 기간 밖에 끝난 판
3. 본 블록 14행(목표 12 + 캐치 2)을 모두 남기지 않은 판 — 서버 전송은 판이 끝났을 때만 일어나므로 실제로는 거의 생기지 않는다

**참가자 단위** — 남은 판을 참가자(`player_id`, 브라우저에 저장된 무작위 번호)별로 모두 합친 뒤:

4. 유효 목표 시행이 10개 미만이거나, 어느 한 조건의 유효 목표 시행이 5개 미만이면 제외 (→ 실수가 적은 한 판만으로도 포함될 수 있다)

**유효 시행의 정의 (이 조건을 모두 만족해야 유효)**

- 본 블록의 목표 시행(캐치 시행·첫 판의 연습 시행 아님)
- `status == 'ok'`
- 반응시간 값이 있음
- 100 ms ≤ 반응시간 ≤ 1500 ms
- 시행 도중 탭 전환·포커스 이탈이 감지되지 않음(`hidden_during_trial == false`)

경고→목표 실제 간격(`cue_target_actual_ms`)과 테두리 실제 점등 시간(`cue_on_actual_ms`)은 프레임 단위로 조금씩 달라진다. 이 값으로 시행을 제외하지 않고, 범위만 보고한다.

## 4. 종속변수

참가자별·조건별로 모든 판의 유효 반응시간을 합친 **중앙값**. 분석 단위는 참가자별 차이 `d = 중앙값(신호 있음) − 중앙값(신호 없음)`. 음수면 신호가 있을 때 빠르다.

중앙값을 쓰는 이유: 반응시간 분포는 오른쪽 꼬리가 길어 평균이 소수의 느린 반응에 끌려간다. 중앙값은 이상값과 절단 기준의 영향을 덜 받는다(Ratcliff, 1993). 판을 거듭하며 빨라지는 학습 효과는 두 조건이 판 안에서 무작위로 섞이므로 두 조건에 같게 들어간다. 판 수가 사람마다 달라 시행 수도 다르지만, 분석은 참가자당 차이값 하나를 쓰므로 많이 한 사람이 결과를 더 많이 좌우하지 않는다.

## 5. 확증 분석과 판정 규칙

- **주 검정**: `d`에 대한 단측 Wilcoxon 부호순위 검정(대립가설: 위치 < 0), α = .05.
  `scipy.stats.wilcoxon(d, alternative='less', zero_method='wilcox', correction=False, method='auto')`, SciPy 1.18.1. 통계량은 W⁺(양수 순위합)로 보고한다.
- **추정치**: Hodges–Lehmann 추정치(Walsh 평균의 중앙값)와, 부호순위 검정을 뒤집어 얻은 정확한 95% 신뢰구간 및 단측 95% 상한.
- **판정**: p < .05 이고 Hodges–Lehmann 추정치 < 0 이면 "가설이 지지되었다". 그 외에는 "지지되지 않았다".
- p ≥ .05는 "효과가 없다"가 아니라 "이 표본으로는 효과를 확인하지 못했다"로 해석한다.

## 6. 보조 분석과 점검 (함께 보고, 판정에는 쓰지 않음)

- **보조 검정**: 단측 대응 t검정, 효과크기 dz, 평균 차이의 95% 신뢰구간과 단측 95% 상한, 부호 검정
- **민감도 분석** (결론이 같은지 확인):
  - (a) RT 하한 150 ms — 신호에 시간을 맞춘 추측 반응을 더 강하게 거른다
  - (b) 참가자별 중앙값 대신 10% 절사평균
  - (c) **참가자마다 첫 판만** — 반복 플레이와 순위표 경쟁의 영향을 뺀 비교
  - (d) **조건별 유효 시행 10개 이상인 참가자만** — 시행 수가 적은 참가자의 잡음을 뺀 비교
  - (e) 최소 검출 효과크기(단측 대응 t검정, 검정력 .80; 주 검정인 Wilcoxon 기준이 아님을 명시)
- **전략 점검** — 원이 아니라 신호에 시간 맞춰 누르는가:
  - 조건별 캐치 시행 오반응률, 참가자별 오반응 수의 조건 차이(양측 부호순위 검정)
  - 조건별 조기 반응 수, 조건별 100–150 ms 반응 비율
  - 신호 조건에서 오반응·조기 반응·빠른 반응이 뚜렷이 많으면, 효과의 일부가 '시간 맞춰 누르기'일 수 있다고 논의에 쓴다.
- **조작 점검**: 첫 판 뒤 한 번 묻는 "테두리가 번쩍이는 걸 봤는가" 응답 분포
- **완료율(기술통계)**: 수집 기간에 시작한 판 중 끝까지 해서 서버에 도착한 판의 비율. 제외 규칙 적용 전 건수이며 검정하지 않는다.
- **참가 양상(기술통계)**: 참가자당 판 수의 중앙값·최댓값, 한 판만 한 참가자 수

## 7. 탐색 분석 (확증이 아님을 논문에 명시)

- 입력 방식별 `d`. 주 입력 방식은 응답의 최빈값, 동률이면 `mixed`. 혼합 입력 참가자도 주 분석에 포함한다.
- 조작 점검 응답(봤다 / 못 봤다·모름)별 `d`
- 판 수(1 / 2 / 3판 이상)별 `d`

## 8. 계획 밖의 분석

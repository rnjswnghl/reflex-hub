# 1단계 — 질문을 가설로

> 과제 안내 1/5 대응: T10-C01 ~ C10

## 관심 분야 (C01)

인지심리 × 사용자 인터페이스. 화면에 미리 주는 시각 신호(경고, 알림 효과)가 사람의 반응 속도를 실제로 바꾸는가.
게임·앱은 "곧 무언가 나온다"는 시각 효과를 자주 쓰지만, 그것이 사용자의 반응을 빠르게 하는지는 대개 검증 없이 쓰인다.

## 검토한 후보 주제 (C02)와 접은 이유 (C03)

| # | 후보 | 결정 | 이유 |
|---|---|---|---|
| A | 경고음 유무가 클릭 반응시간에 주는 영향 | 접음 | 웹에서는 소리의 출력 시점을 통제할 수 없다. 블루투스 이어폰의 출력 지연은 기기마다 크게 다르고, 무음 모드·볼륨·자동재생 차단 때문에 "소리 있음" 조건에서 소리가 실제로 났는지조차 보장되지 않는다. 독립변수 자체가 흔들린다. |
| **B** | **화면 테두리 시각 경고 신호 유무가 단순 반응시간에 주는 영향** | **채택** | 아래 C10 참고 |
| C | 스트룹 과제(글자 의미와 색의 충돌) | 접음 | 색 이름을 읽어야 하므로 한국어 능력과 색각 차이가 결과에 섞인다. 효과가 이미 매우 확립되어 있어 이 연구로 새로 말할 것이 적다. |
| D | 시몬 효과(자극 위치와 반응 방향의 불일치) | 접음 | 좌우 방향키 입력이 필요하다. 모바일 참가자를 포함하면 반응 방식이 기기마다 달라져 조건 통제가 무너진다. |
| E | 힉-하이먼 법칙(선택지 2개 vs 8개) | 접음 | 선택지가 늘면 목표 위치와 손가락 이동 거리도 같이 변한다. 화면 크기가 제각각인 웹 환경에서는 "선택지 수"만의 효과를 분리하기 어렵다. |
| F | 시각 탐색(방해 자극 유무) | 접음 | 휴대폰과 PC의 화면 크기 차이로 목표·방해 자극의 크기와 밀도가 기기마다 달라진다. |
| G | 대기시간 불확실성(고정 3초 vs 무작위 1~7초) | 접음 | 두 조건의 평균 대기시간과 예측 가능성이 동시에 바뀌어 원인을 하나로 특정할 수 없다. 무작위 대기 조건이 세션을 길게 만든다. 앞선 AI 초안은 "네트워크 지연 때문에 버린다"고 적었으나, 반응시간은 브라우저 안에서 측정되므로 네트워크와 무관하다. 그 근거는 틀렸으므로 이 이유로 대체했다. |

## 최종 가설 (C04)

> **목표 자극이 나타나기 500ms 전에 화면 테두리가 100ms 동안 밝아지는 시각 경고 신호가 있으면, 신호가 없을 때보다 같은 참가자의 단순 반응시간이 짧아진다.**

## 무엇이 무엇에 영향을 주는가 (C05)

- 원인(독립변수): 시각 경고 신호의 유무 — 참가자 내 조작, 시행마다 무작위 배정
- 결과(종속변수): 단순 반응시간(ms)
- 방향: 신호가 있을 때 더 짧다 (단측 가설)

## 표현을 어떻게 측정하는가 (C06)

| 가설의 표현 | 측정 |
|---|---|
| 시각 경고 신호 | 화면 안쪽 테두리(안전 영역 안쪽)를 10px 두께로 100ms 점등 (`web/src/styles.css`의 `.cue-frame`) |
| 신호 없음 | 같은 시점에 화면 변화 없음. 목표 자극 시점 분포는 두 조건이 동일 |
| 목표 자극 | 화면 중앙의 흰 원(지름 120px) |
| 반응시간 | 입력 이벤트 시각(`event.timeStamp`, 브라우저가 이벤트를 만든 시각) − 목표 자극을 넣은 프레임 콜백의 시각(`performance.now()`), ms. 화면 표시·입력 장치 지연이 절대값에 섞이지만 두 조건에 같게 들어간다 |
| 짧아진다 | 참가자별 [신호 있음 조건 중앙값 − 신호 없음 조건 중앙값] < 0 이 집단 수준에서 성립 (판정 규칙은 `04-preregistration.md`) |

## 가설이 맞다면 나올 데이터 (C07)

- 참가자 대다수에게서 차이(있음 − 없음)가 음수
- 사전 등록한 단측 Wilcoxon 부호순위 검정에서 p < .05이고, 차이의 Hodges–Lehmann 추정치가 0보다 작음
- 캐치 시행 오반응·100–150 ms 빠른 반응이 신호 조건에만 몰려 있지 않음(효과가 '신호에 시간 맞춰 누르기'가 아님)

**틀렸다면 나올 데이터:** 차이가 0 근처에 흩어지거나 양수(경고가 오히려 방해)가 다수.

## 데이터를 모을 기간과 범위 (C08)

- 기간: 실험 링크를 처음 공유한 날(D0)부터 D0+6일 23:59(한국 시간)까지 7일. 실제 날짜는 `03-design.md` 설계 변경 기록과 논문 방법 절에 적는다.
- 범위: 연구자의 지인과 연구자가 링크를 올린 온라인 커뮤니티 참가자. 목표 20명 이상.
- 중간에 결과를 보고 수집을 멈추거나 늘리지 않는다. 기간이 끝나면 그때까지 완료한 사람 전원을 분석한다. 20명에 못 미쳐도 연장하지 않는다.

## AI와 가설을 다듬은 과정 (C09)

1. **출발 문장**(사용자가 고른 주제): "특정 시각적 이펙트나 경고음의 유무가 사용자의 인지 반응 속도(클릭 시간)에 영향을 준다."
2. **AI가 지적한 결함 세 가지**
   - 독립변수가 두 개(시각 이펙트, 경고음) 섞여 있어, 차이가 나와도 원인을 특정할 수 없다.
   - "이펙트"가 정의되지 않아 측정 방법을 쓸 수 없다.
   - 방향이 없다. "영향을 준다"는 빨라져도 느려져도 맞는 말이라 반박이 불가능하다.
3. **좁히기**: 소리는 웹에서 통제 불가 → 시각 신호만 남김. 효과는 "목표 500ms 전 테두리 100ms 점등"으로 구체화. 방향은 선행연구(경고 신호가 반응을 빠르게 한다는 각성 연구)에 맞춰 "짧아진다"로 지정.
4. **설계 변경**: 처음 제안은 두 집단(A/B 버전)으로 나누는 방식이었다. 반응시간은 사람마다, 기기마다 기본값 차이가 크므로 20~30명 규모에서는 집단 간 비교가 그 차이에 묻힌다. 한 사람이 두 조건을 무작위 순서로 모두 하는 참가자 내 설계로 바꿨다. 같은 기기의 고정 지연은 두 조건에 똑같이 들어가 차이에서 상쇄된다(근거: Pronk et al., 2020 — `02-literature.md`).
5. **최종 문장**: 위 C04.

## 이 가설을 최종으로 고른 이유 (C10)

- **통제 가능성**: 독립변수가 화면 그리기 하나뿐이라 브라우저 안에서 프레임 단위로 제어된다. 로봇 점검에서 기록 로직이 설계대로 동작함을 확인했다(경고→목표 기록 간격 497.5–514.7ms, `docs/evidence/system-check.json`). 실제 화면 표시·입력 장치 지연은 이 점검에 포함되지 않는다.
- **인과 주장 가능성**: 시행마다 조건을 무작위 배정하므로, 차이가 나오면 상관이 아니라 "신호가 반응시간을 바꿨다"는 인과 주장이 이 실험 범위 안에서 성립한다.
- **기기 차이에 강함**: 참가자 내 차이값을 쓰면 기기별 절대 지연이 상쇄된다.
- **반박 가능성**: 방향과 판정 규칙이 미리 정해져 있어, 데이터가 가설을 깰 수 있다.
- **선행 근거 존재**: 실험실에서는 경고 신호가 반응을 빠르게 한다는 결과가 있다. 이 연구는 그것이 통제되지 않은 개인 기기·웹 환경에서도 보이는지를 확인하는 개념적 재현이다.
